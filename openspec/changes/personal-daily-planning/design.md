## Context

见 proposal.md。工作分类和工具共享，不能仅在网关鉴权。现有未提交改动保留，不改治理文件、不运行生产迁移。

## Goals / Non-Goals

目标是完整工作归属及早晚闭环；首版不调用外部模型、不主动推送、不开放外部 MCP。

## Decisions

1. 工作服务向主后端验证 X-Access-Token；内部调用需要密钥、明确用户范围及有效账号，拒绝仅凭用户头认证。
2. 全部工作表加入用户归属，分类唯一键改用户+名称。业务和数据库会话守卫同时覆盖 REST/MCP 及批量操作，关联引用校验同用户。default 保留隔离，不自动认领。
3. AI 请求身份传递到 MCP；22:00 总结按有效用户逐个处理，执行锁和日志按用户，不允许无身份全局处理。
4. Java daily 模块保存个人计划、复盘及设置；本人家庭任务沿用 TaskAssignees 和实时成员验证，日程沿用现有权限，工作通过受限内部接口读取。
5. 用户+日期唯一键防重复，计划版本防并发覆盖；JSON 内容保存来源系统、ID、家庭范围和初始快照。复盘保存引用计划版本和实际截止时刻，用户反馈独立。
6. 每分钟扫描当日 08:30/21:00 应执行项，默认关闭、用户主动启用。当日恢复补跑并标注实际时间；来源失败可重试，不把缺数据定稿为完整计划。
7. 读取历史快照实时过滤无权引用；个人页面不依赖当前家庭选择。首版按优先级和截止日期排序，不估算耗时，不自动延期。

## Risks / Trade-offs

- 旧数据归属未知 → 隔离保留，待指定账号后认领。
- 分类全局唯一 → 迁移复合唯一约束，验证关联及独立未分类。
- 本机停机 → 当日补跑，不承诺离线时准点通知。
- 家庭撤权 → 每次读取快照过滤，存储不等于永久授权。

## Migration Plan

在独立测试库执行工作 Alembic 正逆向及家庭 Flyway 正向/人工逆向脚本。default 不删除，不在业务库执行迁移。部署另行批准，新入口和调度默认关闭。多用户写入后禁止回退到原无隔离应用，回滚保留归属列和数据，恢复安全版本。
