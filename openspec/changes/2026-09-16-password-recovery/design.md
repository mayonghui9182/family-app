# 设计

登录页 → 邮箱申请 → 有界后台发信 → 邮件 fragment 凭证 → 新密码 → 返回登录。
账户找回绑定 user_id，不需要 family_id，也不查询或修改家庭数据。凭证为 32 字节安全随机值，数据库仅存 SHA-256，15 分钟过期；每用户一条，新申请覆盖旧凭证。申请与消费按用户行加锁，消费与密码更新/旧 accessToken 清空同事务。
邮件仅发送到账号登记邮箱，链接主机来自显式配置（默认要求 HTTPS），不读取请求 Host。匿名请求统一 202 受理，后台失败仅记录固定类别不含邮箱/凭证，页面不声称已发出。未配置/队列满直接 503。后台队列内存有界，重启时未发出的请求需重新申请；不持久化明文重置凭证。
来源（直接 remoteAddr，不信任任意代理头）和邮箱摘要使用单实例有界滑动窗口限流；部署多个后端前必须改共享限流。代理部署会保守地按代理 IP 合并计数，需在正式接入时配置可信代理方案。
前端从 fragment 读取凭证并立即清除地址栏，不将其存入持久存储。密码长度沿用 8–64，前端二次确认。匿名接口白名单精确收窄，me/logout/change-password 仍需认证。
V14 新增 password_resets 表，先迁移后发布。回滚先关闭开关、回滚应用后可保留表；物理删除仅在备份后按 Flyway 流程处理。
