## ADDED Requirements

### Requirement: PostgreSQL 16 新增 users / families / family_members / invites 四张表及约束
The system SHALL create four tables via Flyway V4 migration:
- users: BIGSERIAL id, email VARCHAR(120), phone VARCHAR(20), nickname VARCHAR(50) NOT NULL, password_hash VARCHAR(255) NOT NULL, avatar VARCHAR(255), access_token VARCHAR(64), token_updated_at TIMESTAMPTZ, created_at, updated_at, deleted_at. CHECK (email IS NOT NULL OR phone IS NOT NULL). Two partial unique indexes: UNIQUE(email) WHERE deleted_at IS NULL, UNIQUE(phone) WHERE deleted_at IS NULL. idx_users_access_token(access_token) WHERE access_token IS NOT NULL.
- families: BIGSERIAL id, name VARCHAR(50) NOT NULL, description VARCHAR(200), avatar VARCHAR(255), created_by BIGINT NOT NULL REFERENCES users(id) ON DELETE RESTRICT. Index idx_families_created_by.
- family_members: BIGSERIAL id, family_id BIGINT NOT NULL REFERENCES families(id) ON DELETE CASCADE, user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE, role VARCHAR(10) NOT NULL, joined_at TIMESTAMPTZ NOT NULL, left_at TIMESTAMPTZ. UNIQUE(family_id, user_id). CHECK role IN (OWNER,ADULT,CHILD). Index idx_fm_user and idx_fm_active WHERE left_at IS NULL.
- invites: BIGSERIAL id, family_id NOT NULL REFERENCES families ON DELETE CASCADE, inviter_id NOT NULL REFERENCES users ON DELETE RESTRICT, code VARCHAR(6) NOT NULL, max_uses INT NOT NULL DEFAULT 1, used_count INT NOT NULL DEFAULT 0, created_at NOT NULL, expires_at NOT NULL, accepted_at, status VARCHAR(10) NOT NULL DEFAULT ACTIVE. Partial UNIQUE(code) WHERE status=ACTIVE. CHECK status IN (ACTIVE,USED,EXPIRED,CANCELLED). CHECK used_count <= max_uses.
#### Scenario: V4 migration creates 4 new tables on clean PostgreSQL 16
- **WHEN** Flyway migrates from version V3 to V4 on a clean PostgreSQL 16 database
- **THEN** psql shows tables users, families, family_members, invites in addition to tasks, categories; column, CHECKs, partial unique indexes, and FK actions match the spec

### Requirement: 64 hex opaque token + 7 天过期；每次登录重新生成；登出清空
Token SHALL be SecureRandom.getInstanceStrong nextBytes(32) formatted as HexFormat 64 lowercase-hex. Stored in users.access_token with users.token_updated_at. If now() > token_updated_at + 7 days, interceptor atomically UPDATE columns to NULL and return 401 AUTH_TOKEN_EXPIRED. Login UPDATE to freshly generated value and NOW. Logout POST /api/auth/logout sets both NULL.
#### Scenario: Fresh login creates 64-hex access_token with timestamp now
- **GIVEN** Registered user U has access_token=NULL
- **WHEN** POST /api/auth/login succeeds with correct password
- **THEN** users.access_token has length 64 and matches regex ^[0-9a-f]{64}$; token_updated_at within 5 seconds of NOW
#### Scenario: 8-day old token triggers AUTH_TOKEN_EXPIRED and nullifies the row
- **GIVEN** User U has valid access_token ABC, token_updated_at = NOW - 8 days
- **WHEN** U makes any API request with X-Access-Token ABC
- **THEN** interceptor returns 401 AUTH_TOKEN_EXPIRED Chinese 登录已过期，请重新登录; SELECT after shows access_token IS NULL

### Requirement: X-Access-Token + X-Family-Id Header 协议及三档精确 401 码
X-Access-Token SHALL be required on /api/** EXCEPT /api/auth/** /actuator/**. Three precise 401 codes: missing or not-64-hex -> AUTH_HEADER_REQUIRED 请先登录后再操作; not in DB -> AUTH_TOKEN_INVALID 登录状态无效，请重新登录; expired -> AUTH_TOKEN_EXPIRED (previous Req). X-Family-Id required on /api/tasks/** /api/categories/**. On /api/families/{id}/** Service validates independently. Invalid non-member X-Family-Id returns 403 FAMILY_NOT_MEMBER 您不是这个家庭的成员，无法访问.
#### Scenario: Request with no X-Access-Token hits /api/tasks -> AUTH_HEADER_REQUIRED 401
- **WHEN** GET /api/tasks without X-Access-Token
- **THEN** response 401 code AUTH_HEADER_REQUIRED Chinese 请先登录后再操作; downstream Controller not invoked
#### Scenario: Random 64-hex not in DB -> AUTH_TOKEN_INVALID 401
- **WHEN** GET /api/families header X-Access-Token with random 64 hex not stored
- **THEN** response 401 AUTH_TOKEN_INVALID Chinese 登录状态无效，请重新登录
#### Scenario: X-Family-Id points to non-member family -> FAMILY_NOT_MEMBER 403
- **GIVEN** User U is active member only of family 1; headers carry X-Family-Id: 999
- **WHEN** GET /api/categories
- **THEN** response 403 FAMILY_NOT_MEMBER Chinese 您不是这个家庭的成员，无法访问; no data leaked

### Requirement: Register / Login 精确中文错误码；成功响应含 roleName 中文字段
Registration SHALL validate in order: password<8 -> PASSWORD_TOO_SHORT; password>64 -> PASSWORD_TOO_LONG; nickname blank -> NICKNAME_REQUIRED; both email+phone empty -> LOGIN_IDENTIFIER_REQUIRED; bad email format -> EMAIL_INVALID 邮箱格式好像不对，再检查一下; bad phone format -> PHONE_INVALID 手机号格式好像不对，再检查一下; duplicate existing non-soft-deleted email or phone -> USER_DUPLICATED 409 这个邮箱或手机号已经注册过了，直接登录吧. Success transaction: INSERT users -> INSERT families -> INSERT family_members role=OWNER -> generateNewToken -> 201 RegisterAndLoginResponse(accessToken, userId, email, nickname, familyId). Default familyName when omitted is nickname的家. Login POST /api/auth/login four precise codes: AUTH_EMAIL_NOT_FOUND 40111 这个邮箱还没注册哦; AUTH_PHONE_NOT_FOUND 40112 这个手机号还没注册哦; AUTH_EMAIL_WRONG_PASSWORD 40113 邮箱正确，但密码不对，再试试; AUTH_PHONE_WRONG_PASSWORD 40114 手机号正确，但密码不对，再试试. Success LoginResponse: accessToken + nickname + families[] each (id, name, role, roleName, joinedAt) where roleName Chinese (OWNER->家庭管理员, ADULT->成人成员, CHILD->孩子成员).

### Requirement: 9 个 Family/Member 端点 + OWNER/ADULT/CHILD 权限矩阵精确错误码
Nine endpoints SHALL exist: (1) POST /api/families creates family + family_members OWNER; (2) GET /api/families lists my active families; (3) GET /api/families/{id} detail with members[]; (4) PUT /api/families/{id} edits name/description/avatar requires OWNER or ADULT else ROLE_NO_PERMISSION 403 您的角色不能修改家庭信息; (5) DELETE /api/families/{id} returns 501 NOT_IMPLEMENTED 这个功能暂未开放，敬请期待; (6) POST /api/families/{id}/leave requires caller NOT OWNER else OWNER_CANNOT_LEAVE 400 家庭管理员需要先把管理员身份交给其他成员，才能退出家庭; (7) POST /api/families/{id}/transfer-owner requires OWNER caller and target another active adult/child member else OWNER_TRANSFER_TARGET_INVALID 400 请指定一个家庭内的成人成员作为新管理员; (8) POST /api/families/{id}/members/{userId} changes role ADULT<->CHILD requires OWNER; (9) DELETE /api/families/{id}/members/{userId} kicks sets left_at requires OWNER and target NOT OWNER else ROLE_NO_PERMISSION 403 不能踢出家庭管理员，请先转让管理员身份. Service method currentRoleOrThrow(familyId): family not found or soft-deleted -> 404 FAMILY_NOT_FOUND 这个家庭不存在或已被删除; not active member -> 403 FAMILY_NOT_MEMBER; returns role String.
#### Scenario: OWNER tries to leave without transfer -> OWNER_CANNOT_LEAVE 400
- **GIVEN** O is OWNER of family 1
- **WHEN** POST /api/families/1/leave as O
- **THEN** response 400 OWNER_CANNOT_LEAVE Chinese 家庭管理员需要先把管理员身份交给其他成员，才能退出家庭; family_members.left_at stays null
#### Scenario: OWNER transfers OWNER to ADULT, then original OWNER can successfully leave
- **GIVEN** Family 1 has O OWNER and A ADULT both active
- **WHEN** O calls transfer-owner targetUserId=A then O calls leave
- **THEN** after transfer O.role becomes ADULT A.role becomes OWNER; leave succeeds setting O.left_at to NOW
#### Scenario: CHILD role cannot edit family info PUT -> 403
- **GIVEN** C is CHILD of family 1
- **WHEN** C calls PUT /api/families/1 with new name
- **THEN** response 403 ROLE_NO_PERMISSION Chinese 您的角色不能修改家庭信息; families.name unchanged

### Requirement: Invite 邀请码 20 字母表 6 位大写无歧义 + accept 5 精确码 + 原子 consume
InviteCodeGenerator alphabet SHALL be ABCDEFGHJKMNPQRSTUVWXYZ (20 letters; excludes visually ambiguous 0 O 1 I L) producing 6 uppercase chars. UNIQUE collision loops up to 10 attempts; beyond 10 -> ApiException 500 SERVER_ERROR 服务器开小差了，无法生成邀请码，请稍后重试. Four invite endpoints: POST /api/families/{id}/invites (maxUses 1-100 default 1, ttlDays 1-30 default 7, caller role OWNER/ADULT 403 ROLE_NO_PERMISSION 您的角色不能创建邀请，请让家长帮忙操作 for CHILD); GET /api/families/{id}/invites optional status filter OWNER/ADULT; DELETE /api/families/{id}/invites/{inviteId} OWNER OR (ADULT who is also invite.inviter_id) cancels by UPDATE status=CANCELLED; POST /api/invites/accept any logged-in user no X-Family-Id with body {code}. Accept SHALL atomically within single @Transactional: (a) findActiveByCode(code) empty -> 40430 INVITE_NOT_FOUND 邀请码不存在或已过期，请让家人重新生成; (b) now()>expires_at status=ACTIVE -> UPDATE EXPIRED then 40061 INVITE_EXPIRED 这个邀请码已经超过 7 天过期了，请让家人重新生成; (c) used_count>=max_uses status=ACTIVE -> UPDATE USED then 40062 INVITE_COUNT_FULL 这个邀请码次数已用完，请让家人重新生成; (d) user already active member of same family -> 40963 INVITE_ALREADY_MEMBER 您已经是这个家庭的成员了; (e) otherwise used_count++ if >=max_uses status=USED, accepted_at=NOW, INSERT family_members role=ADULT default or UPDATE previous left_at!=null same family+user SET left_at=null role=ADULT joined_at=NOW.
#### Scenario: 10000 generated invite codes contain zero ambiguous characters and are 6 chars uppercase
- **WHEN** InviteCodeGenerator.next generates 10000 codes collected in a test
- **THEN** every code length exactly 6; every character from allowed set; no occurrence of letter 0 O 1 I L lowercase anywhere
#### Scenario: Expired invite accept -> INVITE_EXPIRED and status updated to EXPIRED
- **GIVEN** Invite I status=ACTIVE expires_at=NOW minus 8 days
- **WHEN** User U not member calls POST /api/invites/accept code=I.code
- **THEN** invites.status becomes EXPIRED; response 400 code INVITE_EXPIRED Chinese 这个邀请码已经超过 7 天过期了，请让家人重新生成
#### Scenario: Valid accept atomically consumes invite and inserts family_members; two concurrent accepts on max_uses=2 both succeed
- **GIVEN** Invite I status=ACTIVE max_uses=2 used_count=0; users U1 U2 not in I.family
- **WHEN** U1 accept and U2 accept run concurrently then both complete
- **THEN** invites.used_count=2 and status=USED; family_members gains exactly two new rows role=ADULT; no rows double-counted or missing
#### Scenario: CHILD role invite create blocked 403 with Chinese hint to ask parent
- **GIVEN** C is CHILD of family 1
- **WHEN** C calls POST /api/families/1/invites
- **THEN** response 403 ROLE_NO_PERMISSION Chinese 您的角色不能创建邀请，请让家长帮忙操作; no invite row inserted
