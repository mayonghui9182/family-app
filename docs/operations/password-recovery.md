# 邮箱密码找回：配置与验收

## 当前交付

登录页“忘记密码？” → 输入注册邮箱 → 邮件链接 → 设置新密码 → 返回登录。仅邮箱找回，手机号找回不在一期范围。默认关闭申请服务，未配置时返回明确不可用提示。

接口为 `POST /api/auth/password-reset/request`（email，202 受理）及 `POST /api/auth/password-reset/confirm`（token/password）。请求不需要家庭上下文；凭证绑定账号，不访问家庭业务数据。

## 启用步骤

1. 备份数据库并发布 V14 `password_resets`；当前工作区还含 V13 提醒表迁移，发布时需统一审阅。2026-09-16 已对现有 Compose 数据库完成一次只读归档与隔离全量恢复演练，核心表结构和行数一致；这不代替发布当日的备份。
2. 在部署环境填写以下配置，禁止提交真实密码：
   - `PASSWORD_RESET_ENABLED=true`
   - `PASSWORD_RESET_PUBLIC_URL=https://<实际站点域名>`：仅源站，不能包含用户名、路径、查询参数或 fragment；不从请求 Host 推导。
   - `PASSWORD_RESET_FROM=<已获准发信的邮箱>`
   - `PASSWORD_RESET_SMTP_HOST=<SMTP 主机>`、`PASSWORD_RESET_SMTP_PORT=587`
   - `PASSWORD_RESET_SMTP_USERNAME`、`PASSWORD_RESET_SMTP_PASSWORD`
   - `PASSWORD_RESET_STARTTLS=true`（生产保持 TLS；当前客户端使用 STARTTLS，不是 465 隐式 TLS）。
   - `PASSWORD_RESET_TRUSTED_PROXIES=172.29.0.2`：基础 Compose 已将 nginx 固定为该地址。若部署拓扑改变，只能填后端直接连接的网关完整 IP，不能填客户端网段或 `0.0.0.0/0`。
3. 使用授权测试邮箱验证实收、垃圾邮件目录、链接域名和旧会话失效，再正式开启入口服务。此步骤会发外部邮件，本轮没有执行。
4. 新环境固定 public-tier 地址：nginx 为 `172.29.0.2`、backend 为 `.10`、frontend 为 `.11`、wechat-service 为 `.12`。已有部署必须在维护窗口备份后停止 Compose、确认旧 `familyapp-public-tier` 网络已移除，再按新版 Compose 创建网络并启动；不要在运行中的旧网络上直接尝试分配固定地址。仅修改 `.env` 不会自动进入已有容器。
5. 运行 Compose 配置检查后按正常发布流程重启后端/前端。密码找回默认关闭，真实 SMTP 验收通过前不得将 `PASSWORD_RESET_ENABLED` 设为 `true`。

## 行为与边界

- 32 字节随机凭证、数据库仅保存 SHA-256 摘要、15 分钟有效；每用户最多一条，新申请替换旧链接。邮箱本身未经预先验证也不直接授予改密权，必须持有邮件凭证。
- 消费与密码修改、撤销旧 accessToken 同事务；并发消费只允许一次。
- 邮件链接通过 fragment 传凭证，页面读取后清除地址栏，不存 localStorage/sessionStorage。刷新后需重新打开邮件链接。
- 统一 202 只表示申请受理，不保证邮件已投递；不存在的账号不发信。后台失败不记录邮箱、密码、凭证或链接。
- 邮件队列容量 32、线程数 2，重启会丢弃未发出的申请，用户需重试；凭证原文不落库，因此不是持久化发信队列。队列满或配置不完整返回 50371。
- 限流为单后端进程：每来源申请 10 次/15 分钟、每邮箱 3 次/15 分钟、每来源确认 30 次/15 分钟，窗口最多 10000 个键；重启清空。多副本上线前必须改用共享限流。
- nginx 位于固定 `172.29.0.2`，后端只在直接连接来自该地址时采用单值 `X-Real-IP`；任意 `X-Forwarded-For`、多值或无效头均回退到直接来源。不要将整个容器网段加入白名单，否则同网段服务可能伪造客户端 IP。若部署拓扑改变，先更新完整网关 IP 并重做伪造头验收。
- 关闭 `PASSWORD_RESET_ENABLED` 停止新申请；已发链接仍可在有效期内完成确认。需要紧急撤销时由运维作废重置表记录并保留审计。
- 登录 `me/logout/change-password` 已从原本宽泛的匿名认证路径中收窄；未登录 `me` 统一返回 40100（此前 40103）。

## 本轮验收

- 后端测试包含替换/过期/错误链接、并发消费、旧会话撤销、匿名路径、受理响应和发信配置边界。
- 前端测试覆盖申请失败与受理、密码确认、清理地址栏/旧会话、缺失凭证和页面切换。
- 本机 H2 + 只接收不转发的 SMTP + 375px Chromium：登录入口、申请实收、邮件链接重置、旧 token 无效、重复链接拒绝、新密码登录通过；已查看中文截图。
- PostgreSQL 16 隔离库：V14 正向迁移、写入/消费、事务回滚、删表回滚及物理撤销通过。另已对当前 Compose 数据库执行只读归档，并完整恢复到无网络、无端口的临时 PostgreSQL，核心表结构和行数一致；临时归档和容器已清理。

## 回滚

关闭申请开关，回滚应用代码，保留 V14 表即可；不影响原任务数据。确需移除时先备份，执行 `DROP TABLE password_resets` 并按团队 Flyway 版本管理流程处理迁移历史；不要直接删除生产迁移历史再运行新版。

本轮未部署、未配置真实发信凭据、未向外部邮箱发信。真实 SMTP 验收和代理限流部署评估仍为发布前待办。
