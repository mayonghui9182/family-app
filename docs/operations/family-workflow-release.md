## V13 提醒表
新增 task_notifications，任务创建和提醒入队同事务，定时作业提交抢占事务后再调用微信。
状态为 PENDING/SENDING/SENT/SKIPPED/FAILED，属于提醒状态，不改变任务五值状态机。
租约 5 分钟，失败指数退避，最多 5 次；平台未配置模板等明确跳过记录为 SKIPPED。
异常退出后租约到期重新处理。微信外部发送无法与本地数据库组成原子事务，发送成功后进程立即崩溃仍可能重复提醒；不宣称恰好一次。

回滚：先关闭提醒调度或停止新后端，恢复旧后端代码，保留新表供排障。确需物理撤销时，在完成备份且确认提醒记录不再需要后执行 `DROP TABLE task_notifications;`；同时按 Flyway 管理流程处理 V13 历史，禁止直接删除生产迁移历史后继续运行新代码。

## 备份与演练
在仓库根目录运行 `bash scripts/backup-postgres.sh /srv/family-backups`。设置每天定时执行，并将成功的 .dump 复制到另一台机器或备份存储；限制目录权限。
恢复演练应在空的隔离数据库执行 `pg_restore --exit-on-error --no-owner --dbname=<隔离数据库> <备份文件>`，然后核对家庭、任务数量与最新任务，验证业务账户权限。脚本检查归档可读，不代替实际恢复演练。
如需更小的数据丢失窗口，应另行配置 WAL 归档与时间点恢复。

## 必验用户流程
1. 用档案指派任务，检查本人列表、本人统计及提醒投递状态；编辑更换/清空执行人。
2. 点击本人逾期，切换家庭并模拟慢请求。
3. 创建 AI 草稿后修改日期，关闭再打开，确认只创建一批任务。
4. 微信草稿深链登录后恢复原页，修改、确认并再次打开查新任务。
5. 任务分页、首页数据加载失败、微信暂不可用时仍可保存任务。
