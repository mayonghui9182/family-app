# 执行约定 v0.2

## 五阶段与现有流程

五阶段是业务评审视角，项目 Harness 是每次会话的执行协议，两者同时遵守。OpenSpec 决定产物的实际路径和依赖顺序，不通过本包改 schema。

| 阶段 | 输出与工作 | 结构校验要求 |
|---|---|---|
| 1 需求整理与拆分 | 输入基线、范围/非目标、change 依赖、R、问题表、覆盖矩阵 | R 来源/验收、编号唯一、覆盖行完整 |
| 2 架构 | 跨 change 接口、数据流、选型或复用理由 | 补架构列 |
| 3 详设与任务 | design、tasks、验证方案，按需 UI 溯源 | 补设计、任务、验证项；所有任务有依据 |
| 4 开发 | 实现与检查结果 | 已完成任务关联实现及证据；未完成任务保留 |
| 5 验收 | 关键要求逐项核验、其余约定测试/风险抽查、回归 | 全部任务完成，适用实现/证据齐全，问题已处置 |

阶段评审记录放 verification.md：阶段、输入版本、评审人、日期、结论、问题/证据。脚本不判断评审是否真实。高风险需求须逐项验证，抽查不能代替它。阶段4可多次运行，不要求所有任务已完成。

## 输入预处理

原始材料处理见[材料解析](parsing.md)。原件摘要为版本依据，生成MD为阅读副本；先处置解析异常，不能将损坏、未支持或OCR待办当作“没有需求”。将provenance中的章节/表格/单元格/DOM出处写入来源，R正文仍仅维护在spec。
解析清单与需求覆盖矩阵属于不同检查，前者不能证明业务需求完整，后者不能发现从未提取的原始内容。

## 需求与依据

每个 change 是可独立验证的变更单元，允许功能、技术或探索类型；明确依赖与交付顺序。一次任务尽量在一次会话完成，文件数仅作预警。

R 只记录材料明确内容或已确认决策；检查正常/分支/异常边界/权限/数据兼容/交互/质量要求，未说明记问题，确认不适用才写不适用。
R 编号支持 R-001 或 C-02-R-001，全 change 内唯一，废弃后不重用、不重排。跨 change 引用通过明确来源记录，不将相同业务正文复制维护。
技术任务引用 design.md 中的 TC/AD 条目，每条须说明内容、来源及确认记录。技术依据不能绕过业务负责人决定业务行为。
spec 使用 OpenSpec Requirement/Scenario 语法；依据模板添加 R 编号、来源、状态、验收字段。废弃条目仍保留来源记录，正式移除/归档按当前 schema 执行。

## 最小记录及格式

本版脚本适用于模板约定：sources.md、questions.md、coverage.md 在 change 根目录；spec 在 specs/**/spec.md；任务为 tasks.md；技术依据在 design.md。
有共享来源时，sources.md 引用共享材料的固定版本即可，无需复制。
所有 Markdown 表格每个单元格单行，单元格内竖线使用全角「｜」；不要嵌套表格、换行或使用代码围栏包住正式表格。
来源写为「S-001 / 章节或区块」，来源登记版本和定位；外链内容、版本真实性及章节是否存在由人工核实。
覆盖列只存标识或引用；多引用用英文逗号分隔。任务编号复用 OpenSpec 数字编号，例如 1.1。
映射未到阶段可写「未完成」；待确认写「待确认：Q-001」；变更后写「待复核：原因」；不适用写「不适用：理由」。R 的任务和验证项不能不适用。
架构/设计/验证项引用采用「相对文件路径#定位」，脚本仅检查文件存在，定位语义由人核查。
实现与证据也采用文件引用，允许 ../ 指向源码或证据目录。不读取或执行被引用文件，URL 不作为本版文件证据；外部报告先登记本地证据索引。
实施证据须写明被测版本、环境、日期、命令或检查动作、预期/实际结果；文档/探索任务使用合适的审阅或实验记录。

任务格式：`- [ ] 1.1 描述 [依据：R-001, TC-001]`。技术任务单独写在 coverage.md 技术任务表，与 R 行分开；同一任务也可同时有业务和技术依据。
待确认问题中的「阻塞阶段」填最早受影响阶段1–5；非阻塞填0。状态为待确认/已解决/不适用；后两者必须有结论。0不阻塞结构校验，验收仍需处置。

## 原型和变更

原型按稳定区块编号，允许一个区块映射多个 change。切片保留必要视觉及交互状态；AI只做小片段归类，无法判断标待定。
UI 按逻辑元素登记编号、区块、出现条件、R或展示设计、数据来源、展示计算规则、文案来源；重复列表按模板登记。接口字段可用于展示、控制或内部处理。
DOM 提取只是候选，人工补查弹窗、错误和权限状态。不强制引入 i18n，沿用项目约定。
上游变化记录旧/新版本、原因、影响及裁决；受影响映射改为待复核，复用旧证据必须写依据。

## 校验边界

脚本检查重复编号、来源登记、失效引用、阶段必填映射、任务依据、证据文件存在、阻塞问题。编号断号合法。
脚本不证明需求无遗漏、确认人真实、引用语义正确、测试充分或实现正确，不替代 OpenSpec validate/status。
